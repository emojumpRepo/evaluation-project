# 测评模块产品需求文档 (PRD)

## 1. 背景与目标

### 1.1. 项目背景
为了满足多样化的心理、能力、发展等评估需求，我们需要一个灵活的测评系统。当前，许多专业的问卷（量表）已经由外部系统或第三方服务实现。本系统的核心目标是**编排和管理**这些外部问卷，将它们组合成一个完整的“测评活动”，并统一管理测评的发布、执行与结果。

### 1.2. 核心目标
- **高效创建测评**：管理员可以快速地将多个独立的外部问卷组合成一个结构化的测评。
- **灵活关联问卷**：测评与问卷解耦，问卷可以被多个不同的测评复用。
- **统一结果管理**：即使用户在外部链接完成问卷，本系统也需要能够接收并存储每一次的问卷结果，并自动汇总成一份总的测评报告。
- **清晰的用户体验**：为终端用户提供一个清晰、连贯的测评流程，引导他们完成测评中的所有问卷。

## 2. 功能范围

### 2.1. 核心功能模块

| 模块 | 功能描述 |
| :--- | :--- |
| **问卷管理** | 管理所有可用的外部问卷信息，核心是问卷链接。 |
| **测评管理** | 创建和定义测评活动，将一个或多个问卷关联进来。 |
| **测评执行** | 用户参与测评，访问并完成各个问卷的流程。 |
| **结果管理** | 存储、展示和管理用户完成的问卷结果与最终的测评总结果。 |

### 2.2. 目标用户
- **管理员**：系统的主要使用者，负责创建、配置和管理问卷与测评，并查看最终结果。
- **终端用户** (如：学生、员工): 测评的参与者，负责完成整个测评流程。

## 3. 功能详述

### 3.1. 问卷管理 (`emo_questionnaire`)

管理员可以在此模块中对外部问卷进行增、删、改、查操作。

| 功能点 | 描述 | 关键字段 |
| :--- | :--- | :--- |
| **新增问卷** | 录入一个外部问卷的信息。 | `title`, `description`, `link` (必填), `type`, `status` |
| **编辑问卷** | 修改已录入问卷的信息，如更新链接或描述。 | - |
| **查询问卷** | 按标题、类型、状态等条件搜索和筛选问卷。 | - |
| **管理状态** | 控制问卷的生命周期，如“草稿”、“已发布”、“已下线”。 | `status` |

### 3.2. 测评管理 (`emo_assessment` & `emo_assessment_questionnaire`)

| **编辑测评** | 修改测评的基本信息。 | - |

### 3.3. 测评执行 (用户流程)

终端用户参与测评的完整流程。

1.  用户选择并进入一个“已发布”的测评。
2.  系统展示该测评包含的所有问卷列表（按 `sort_order` 排序）。
3.  用户点击第一个问卷，系统在新窗口或跳转到该问卷的外部 `link`。
4.  **（关键交互）** 用户在外部系统中完成问卷。完成后，外部系统需要通过回调机制或页面重定向，将结果数据（如分数、JSON数据等）传回本���统。
5.  本系统接收到结果后，在后台创建一条 `emo_questionnaire_result` 记录，并更新测评主页面的状态（如标记该问卷为“已完成”）。
6.  用户返回测评主页面，继续完成下一个问卷，重复步骤 3-5。
7.  当所有 `is_required` 为 true 的问卷都完成后，系统判定整个测评完成。

### 3.4. 结果管理 (`emo_assessment_result` & `emo_questionnaire_result`)

系统自动记录和处理用户提交的结果数据。

| 功能点 | 描述 | 触发时机 | 涉及表 |
| :--- | :--- | :--- | :--- |
| **创建测评总结果** | 当用户首次开始一个测评时，系统为他创建一条总结果记录，状态为“进行中”。 | 用户开始测评时 | `emo_assessment_result` |
| **保存问卷子结果** | 接收并存储用户在外部完成的单个问卷的结果。 | 外部问卷回调时 | `emo_questionnaire_result` |

## 4. 数据模型

本需求的实现依赖于以下核心数据表，它们之间的关系构成了业务逻辑的基础。

-   `emo_questionnaire`: 问卷信息主表。
-   `emo_assessment`: 测评信息主表。
-   `emo_assessment_questionnaire`: 测评与问卷的多对多关联表，是定义测评结构的核心。
-   `emo_assessment_result`: 存储用户测评的总体结果，是结果的父表。
-   `emo_questionnaire_result`: 存储用户单个问卷的完成结果，是结果的子表，通过 `assessment_result_id` 关联到父表。

这种设计清晰地分离了**“定义”**（测评包含什么）和**“实例”**（用户完成的结果），具备良好的扩展性。

## 5. 非功能性需求

- **安全性**: 只有授权用户才能参与测评，管理员需要权限才能管理模块。
- **易用性**: 管理员操作界面应清晰直观，特别是关联问卷的操作要方便。
- **可靠性**: 结果数据必须准确无误地保存，回调机制需要稳定可靠。
